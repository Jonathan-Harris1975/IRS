DEPENDENCY / LOCKFILE POLICY
----------------------------
- Dependabot is retained but open-pull-requests-limit is set to 0. This preserves its repository configuration as a Scorecard signal without allowing Dependabot version-update PRs.
- Mend Renovate remains the dependency-update owner.
- Renovate lockFileMaintenance is enabled.
- Renovate npm updates are configured to keep package manifests and package-lock.json synchronised in the same PR.
- Renovate patch/minor/digest updates, including GitHub Actions where detected, may automerge only after the stability window and required checks pass; major updates remain manual.
- Existing npm ci verification remains in place and will fail when dependency manifests and package-lock.json are incompatible.

OWASP ZAP
---------
ZAP remains an ecosystem-level monthly DAST control rather than a per-PR IRS repository check. No ZAP secret or target URL has been added to IRS by this change.

AUTOMATION / SCHEDULE POLICY
----------------------------
- GitHub scheduled CI controls (CodeQL, repository security/quality, and the scheduled live-target audit) are aligned to Saturday at 19:00 UTC using cron `0 19 * * 6`.
- Push and pull-request CI remains immediate; the Saturday schedule is additional recurring assurance and does not delay change validation.
- Renovate is restricted to Saturday 19:00-21:30 Europe/London. Mend's hosted scheduler may start work within the configured window rather than at an exact second.
- Renovate automatically merges npm patch/minor updates and lockfile-maintenance PRs only after required branch/CI checks permit the merge.
- Major updates remain manual. Patch/minor/digest updates follow the committed Renovate automerge policy and still require repository checks.
- package-lock.json is updated by Renovate together with dependency manifest changes and is verified by npm ci.

AUTONOMOUS PROVING-GROUP SETUP
- Scheduled window: Saturday 19:00 UTC; 2.5 hours reserved before the next repository starts.
- KiloConnect + Kilo Code Bot: authorise both GitHub integrations for this repository. Failed default-branch CI/deployment-watch runs create one deduplicated repair PR and invoke @kilocode-bot in PR context.
- Kilo may prepare dependency-manifest/lockfile/build fixes when evidence requires them, but all changes remain PR-only and must pass existing gates.

- Enable Kilo Code Reviews for this repository and enable REVIEW.md guidance in the Kilo Code Reviews configuration.
- Kilo Code Reviewer remains review-only, but trusted automation watches its PR comments. When a Kilo review says `Reply with @kilocode-bot fix it`, the default-branch control plane posts that exact implementation command automatically after trust/path checks; no human reply is required.

AUTONOMOUS REPAIR + TRUSTED PR AUTOMATION
-----------------------------------------
- Required repository variable: AUTONOMY_REPAIR_APP_ID.
- Repository secret name is `AUTONOMY_REPAIR_APP_PRIVATE_KEY`; store the PEM private key generated for the installed Autonomous Repair Bot GitHub App in that secret.
- Required GitHub App repository permissions: Contents read/write, Pull requests read/write, Issues read/write, Actions read/write, and Metadata read-only (automatic).
- Actions read/write is used only by `.github/workflows/trusted-automation.yml` to admit workflow runs that GitHub has placed in `action_required` for a verified automation PR, with a safe rerun fallback for the same exact trusted PR/SHA. It is not a branch-protection bypass.
- The trusted workflow runs from the default branch, never checks out or executes PR code, and admits only: exact same-repository Mend Renovate PRs, autonomous carrier PRs created by the repair App, and Kilo implementation PRs explicitly linked from a trusted carrier or trusted Renovate PR that automation handed to Kilo.
- Fork secrets and write tokens remain disabled. An unlinked Kilo PR or any unknown bot/user PR is not automatically admitted.
- Renovate PRs may be admitted to run CI regardless of update type. Native auto-approval/auto-merge is requested only when the Renovate PR body explicitly reports `Automerge: Enabled.`; major/manual Renovate PRs remain manual as defined by committed `renovate.json` policy.
- A verified linked Kilo implementation PR may be approved only after the current head SHA has successful repository CI, CodeQL and repository-security workflows and no current failing/pending checks.
- Kilo/carrier changes to workflows, Renovate/Mergify configuration, CodeQL/security policy, secret-scanner controls, CODEOWNERS, SECURITY.md or autonomy governance files automatically receive `autonomy:human-hold` instead of autonomous merge.
- `.mergify.yml` performs lifecycle housekeeping only: it may close `autonomy:superseded` and `autonomy:obsolete` PRs, but it does not merge code.
- Native GitHub auto-merge / Merge Queue is the final merge authority. Trusted automation can request native auto-merge only after the exact-head checks are green; GitHub branch/ruleset protections remain authoritative.
- Keep GitHub automatic deletion of merged head branches enabled where desired to remove completed automation branches.
- CodeQL findings remain an independent merge gate without turning a successful analysis into an artificial CI failure. Trusted automation extracts policy-safe findings/check annotations, posts `@kilocode-bot fix it` automatically, and blocks native auto-merge until the findings clear. Alert dismissal, broad suppressions, secret/allowlist changes and security-policy decisions remain human-controlled.
